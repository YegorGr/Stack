# Stackность

## Taskность
Требовательность создательность кодности, что способность пушность и попность numberность. Стек работает пока что только для чисел double, но также планируется в будущем масштабировать задачу. В `#typedef` в файле `Stack.h` можно изменить зачение `#define TYPE_STK double` на другое значение. Пока этой опицией советую не пользоваться, т.к. распечатка значений в `StackDump()` пока не продумана для зачений, имеющий любой другой отличный от `double`. Также значения `POISON` и `CANARY` пока доступны только для double.

## Архитектурность проекта
Два файла: `stack.h` и `main.c`. Файл `stack.h` инклюдится в `main.c`. 

## Что можно делать со стеком?

* Пушить данные в стек с автоматическим расширением.
* Попить данные из стека.

## Запускность программы
Для запуска стека в режиме полной проверки при компиляции поставить флаг: `-DON_DEBUG`

```text
g++ main.c DON_DEBUG
```

Для запуска стека в режиме быстрой работы при компиляции убрать флаг: `-DON_DEBUG`

```text
g++ main.c
```

## Фичность 

### Security protection very safy function  
Массив, который хранит элементы стека обладает канареечной защитой. (Защищен с двух сторон двумя канарейками: `#define CANARY -3.1415926535`).
Также сама структура стека защищена двумя канарейками: `#define LEFT_CANARY_STK 0xC0FFEE`, `#define RIGHT_CANARY_STK 0xDADDED`. 

### Макросность
В программе есть макрос `asserk_ok(stk)` --- работает в режиме `ON_DEBUG`. Этот макрос вызывает функцию `StackOk()` и при необходимости `StackDump()` (если целостность стека нарушена).

### Несколько уровней защиты (в ближайшем будущем)
На данный момент организовано две канареечные защиты, защита хешами, а также проверка разнообрных случаев нулевых указателей. Проверка на `POISON`. В ближайшем обозримом будущем хочется сделать включение уровней защиты независимо друг от друга. 

### Алгоритм хеширования
Был выбран алгоритм djb2 (Дж. Бернштейн), в силу простоты самого алгоритма, его скорости. И относительно хорошей надежности. В приоритете при выборе была скорость.
